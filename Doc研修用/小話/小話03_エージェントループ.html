ChatGPTでのチャットとは、ここが決定的に違う

チャット（今まで触ったもの）エージェント（今日使っているもの）
できること文章を返す読む・書く・実行する
呼び出し回数1往復で1回目的達成まで何十回も
終わり方答えを返したら終了目的を達成するまで止まらない
待ち時間数秒数分〜十数分
🎤 話すこと（登壇メモ）
  • 実行ボタンを押してから数分。じっと待っていると「AIが悩んでいる」ように見えますが、実際にはファイルを読んで、書いて、コマンドを叩いて、エラーを読んで、直してを延々と繰り返しています
  • 皆さんが手作業でやることと、やっている作業自体は変わりません。ただ、それを止まらずに回し続けている
  • 手元のログを見てください。いま何番目のファイルを触っているか、見えるはずです
SLIDE 2 中身と持ち帰り
賢いのは「毎回1発の判断」。
それを繋いでいるのは、ただのループ

中身は、驚くほど素朴なプログラム

while (終わっていない) {
    出力 = LLMを呼ぶ(これまでの全経緯);   // ← 賢いのはココだけ
    if (出力がツール呼び出し) {
        結果 = ツールを実行する();          // 検索する / ファイルを読む / mvnを叩く
        これまでの全経緯 += 結果;           // ← 末尾に足す
    } else {
        break;                            // 文章を返してきた＝完了
    }
}

役割分担はこうなっている

🧠
判断 ── LLM（1つだけ）
次に何をすべきか。
毎回まっさらな1発の推論で決める
⚙
実行・接続 ── ただのプログラム
ツールを実行し、結果を末尾に足して、
もう一度LLMを呼ぶ
❌ よくある誤解
指揮者AIがいて、専門AIに仕事を振っている
✅ 実際
同じ1つのモデルが、1行ずつ増えていく経緯を毎回読み直して、そのつど次の一手を決めている

ループが止まる3つの条件

🟢 目的達成
ビルドが通った、テストが緑になった
🟡 手詰まり
自分で直せないと判断した
🔴 上限到達
回数・トークンの上限に当たった
⏳ 待ち時間 ＝ AIの作業時間 長いのは、それだけ仕事をしている証拠

🎁 Take away

  • ⏳待ち時間 ＝ AIの作業時間。長いのは、それだけ仕事をしている証拠
  • 🔍ログは最良のデバッグ情報。「何を読んだか」「どこで詰まったか」が全部書いてある。うまくいかない時はまずログを遡る
  • 🔧道具を与えるほど自走する。ビルドやテストを実行させると、AIは自分で誤りに気づいて直せる（＝今日のCD／UTの構成そのもの）
  • ⚠毎回「全経緯」を読み直している ＝ ループが長引くほど経緯が膨らむ。これが次の話に直結する→ 小話02
🎤 話すこと（登壇メモ）
  • ChatGPTでチャットした時との一番の違いはここです。あちらは「文章を返して終わり」、今日のものは「目的を達成するまで自分で回り続ける」
  • そして意外なのが中身の素朴さです。裏で何体ものAIが連携しているように見えますが、実際には賢い部分は1つのモデルだけで、周りはただのループなんです
  • しかも各判断は毎回1発です。前回何を考えたかを覚えているわけではなく、増えていく経緯を毎回まるごと読み直して、そのつど決め直している
  • だから止まった時に見るべきは、出力の最後ではなくループの途中です。「設計書を読めていない」「同じエラーで3回ループしている」は、ログを見ればすぐ分かります
  • ……そして、毎回まるごと読み直すということは、長く回すほど読む量が増えるということでもあります。それが次の小話につながります
