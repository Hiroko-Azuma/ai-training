# 小話08　モデルの選び分けと知識カットオフ

|項目|内容|
|---|---|
|分類|🔧 仕組み|

## スライド1

### メインメッセージ
> **モデル選びは「賢さ」ではなく「賢さ × 速さ × 単価」の3すくみ**

### 見せるもの

**掴み：モデル名がやたら多い。結局どれを選べばいいのか**

```
        賢い・遅い・高い
              ▲
              │   ◆ 上位モデル
              │      設計／難所の実装／原因不明の障害調査
              │
              │        ◆ 中位モデル
              │           通常の実装・テスト作成
              │
              │              ◆ 軽量モデル
              │                 定型変換・要約・分類・大量処理
              └──────────────────────────►
                             速い・安い
```

**選び分けの目安**

| 仕事の性質 | 選ぶもの | 理由 |
|---|---|---|
| 🧠 **考えさせる**（設計・難所・調査） | 上位モデル | 失敗のコストが、単価差より圧倒的に高い |
| 🔨 **作らせる**（設計書どおりの実装） | 中位モデル | 情報を渡せているなら差が出にくい |
| 🔁 **捌かせる**（定型変換・分類・大量処理） | 軽量モデル | 速さと単価が効く。品質差が出にくい領域 |

> 💡 **難しいのはモデルではなく「渡す情報」の方が多い**（→ 小話10・13）
> 上位モデルに変える前に、設計書を渡せているかを疑う

### 話すこと
- 一番よくある質問が「どのモデルを使えばいいですか」です。答えは「**仕事の性質で変える**」なんですが、もう一歩踏み込むと…
- **モデルを上げる前に、情報を渡せているかを見てください**。情報不足が原因の失敗は、上位モデルに変えても直りません
- 逆に、設計・難所の切り分けのような「考える」仕事はケチらない方がいい。**やり直しのコストの方が高い**です

## スライド2

### メインメッセージ
> **どのモデルにも共通する弱点が「知識の締切」**

### 見せるもの

**学習データには断面がある**
```
 ────────── 学習データ ──────────┃            ？？？
 2020        2023        2025    ┃ ◄── ここから先は
                       学習の締切日┃      どのモデルも知らない
                                  ┃
                            今日 ─┘
```

**だから、こういう事故が起きる**

| 症状 | 実際に起きていること |
|---|---|
| 古いバージョンの書き方で書いてくる | 締切時点で主流だった書き方を出している |
| 存在しない新APIを"知っている風"に使う | 断片的な情報から、それらしく補完している |
| 非推奨のライブラリを勧めてくる | 締切以降の変更を知らない |

**対策は1つ：知らないなら、渡す**
```
 ① 使うバージョンを明記する
      「Spring Boot 3.5.8 / Java 21 で書いてください」
 ② 公式ドキュメントの該当箇所を渡す（または検索させる）
 ③ 既存の動いているコードを見本として渡す  ◄── 最強
```
→ ③は今日の `CD_ルール.md` のサンプルコードそのもの（→ 小話14）

### Take away
- ✅ **モデルは仕事の性質で選ぶ**。考える仕事はケチらない、捌く仕事は軽量で足りる
- ✅ 精度が出ない時、**最初に疑うのはモデルではなく渡した情報**
- ⚠ **どのモデルにも締切日がある**。最新ライブラリ・最新仕様は、こちらから与える
- 💡 一番効くのは「**動いている既存コードを見せる**」こと。バージョンも作法も一度に伝わる

### 話すこと
- カットオフの話で押さえてほしいのは、「新しいモデルなら大丈夫」ではないことです。**新しいモデルにも、その時点の締切がある**
- 現場で効くのは、バージョンを書くことと、**既存の動いているコードを見本に出す**ことです。「これに倣って」の一言が、細かい指示100行より効きます
- 今日の研修で `CD_ルール.md` にサンプルコードが載っているのは、まさにこの理由です

## 補足（質問が出たら）
- **Q. Web検索できるなら締切は関係ない？** → 検索できる情報なら解決する。ただし社内固有の情報は検索しても出てこない（→ 小話05）
- **Q. モデルを変えたら結果が変わる？** → 変わる。ルールとテストで縛っておけば影響は小さくできる（→ 小話06）
