# 小話07　AIは文字を数えられない ―「strawberryのrは何個？」

|項目|内容|
|---|---|
|分類|🔧 仕組み（箸休め）|
|尺|3分（スライド2枚）|
|推奨タイミング|短い待ち時間／空気が重くなった時|

---

## スライド1

### メインメッセージ
> **あれだけ賢いのに、小学生でもできる事を間違える**

### 見せるもの

**掴み：やってみてください**
```
 Q. strawberry の中に "r" は何個ありますか？
 Q. 8127 × 349 は？
```
→ かつては、平然と間違えた（今も条件次第で間違える）

**理由：AIは文字を見ていない。トークンを見ている**
```
 人間が見ているもの    s t r a w b e r r y     ← 1文字ずつ数えられる

 AIが見ているもの     [ st ][ raw ][ berry ]   ← 3つの塊
                        ▲
                        この塊の中に "r" が何個入っているかは
                        塊の外からは見えない
```
- 数字も同じ。`8127` が `[81][27]` のような塊で入ってくる
- 筆算をしているのではなく、**「それらしい数字の並び」を生成している**（→ 小話05）

### 話すこと
- これ、AIの限界がいちばん分かりやすく出る例です。難しい設計はできるのに、文字数えは苦手
- 理由は単純で、**AIは文字ではなくトークンという塊で世界を見ている**からです（→ 小話04）
- 計算も同じで、計算しているのではなく**計算結果らしい文字列を書いている**だけです

## スライド2

### メインメッセージ
> **苦手なことは、道具にやらせればいい ── それがAgentの存在意義**

### 見せるもの

**今のAIが正解できるようになった理由**
```
 ❌ 昔： 頭の中で数えようとする      →  それらしい数字を書く
 ✅ 今： 「これは数えるタスクだ」と判断
          ↓
        コードを書いて実行する
          "strawberry".count("r")  ─►  3
          ↓
        実行結果を根拠に答える
```
→ **賢くなって数えられるようになったのではなく、数えるのをやめて機械に任せた**
→ 小話05の「Web検索で天気を取ってくる」とまったく同じ構造

**この線引きが、そのまま実務の使い分けになる**

| ❌ AIに直接やらせない | ✅ AIに"やらせ方"を作らせる |
|---|---|
| 件数を数える／集計する | 集計するSQL・スクリプトを書かせて実行 |
| 計算する | 計算するコードを書かせて実行 |
| 正確な変換・置換 | 変換ロジックを書かせて実行 |
| 網羅チェック | チェックするテストを書かせて実行 |

### Take away
- ✅ **「AIに答えを聞く」より「答えを出す道具を作らせる」**方が、桁違いに正確
- ✅ 数える・計算する・正確に処理する系は、**必ず実行結果を根拠にさせる**
- ✅ 今日のハンズオンで `mvn compile` や UT を回させているのも、これと同じ発想
- ⚠ 逆に言えば、**検証手段のないタスクほど危ない**（→ 小話19 得意・苦手）

### 話すこと
- 笑い話に見えますが、実務上とても大事な線引きが入っています
- 「AIに聞く」のではなく「**AIに、答えが出る仕組みを作らせて、その結果を見る**」。この癖をつけるだけで精度が変わります
- 今日の研修でAIにビルドやテストを実行させているのは、まさにこれです。**AIの言い分ではなく、機械の結果を信じる**という設計になっています
