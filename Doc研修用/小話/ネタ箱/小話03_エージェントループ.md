# 小話03　いま、画面の向こうで何が起きているのか

|項目|内容|
|---|---|
|分類|🔧 仕組み|
|尺|6分（スライド2枚）|
|推奨タイミング|一番最初の長い待ち時間（CD実行中）|

## スライド1

### メインメッセージ
> **この5分、AIは「考え込んでいる」のではなく「手を動かしている」**

### 見せるもの
```
        ┌─────────────────────────────┐
        │                             ▼
   ① 考える(Think)  ──►  ② 道具を使う(Act)  ──►  ③ 結果を見る(Observe)
   次に何をすべきか       ・設計書を読む            ・読んだ中身
   を判断する            ・ファイルを書く          ・ビルドのエラー文
        ▲                ・mvn を叩く             ・テスト結果
        │                                             │
        └─────────────────────────────┘
                     目的を達成するまで繰り返す
```

- いま画面に流れているログが、そのまま①②③の記録になっている
- 「Read 〇〇.md」「Edit BookController.java」「Run mvn compile」＝②の実行ログ

**ChatGPTでのチャットとは、ここが決定的に違う**

|  | チャット（今まで触ったもの） | エージェント（今日使っているもの） |
|---|---|---|
| できること | 文章を返す | **読む・書く・実行する** |
| 呼び出し回数 | 1往復で1回 | **目的達成まで何十回も** |
| 終わり方 | 答えを返したら終了 | 目的を達成するまで止まらない |
| 待ち時間 | 数秒 | **数分〜十数分** |

### 話すこと
- 実行ボタンを押してから数分。じっと待っていると「AIが悩んでいる」ように見えますが、実際には**ファイルを読んで、書いて、コマンドを叩いて、エラーを読んで、直して**を延々と繰り返しています
- 皆さんが手作業でやることと、やっている作業自体は変わりません。ただ、それを止まらずに回し続けている
- 手元のログを見てください。いま何番目のファイルを触っているか、見えるはずです

## スライド2

### メインメッセージ
> **賢いのは「毎回1発の判断」。それを繋いでいるのは、ただのループ**

### 見せるもの

**中身は、驚くほど素朴なプログラム**
```java
while (終わっていない) {
    出力 = LLMを呼ぶ(これまでの全経緯);   // ← 賢いのはココだけ
    if (出力がツール呼び出し) {
        結果 = ツールを実行する();          // 検索する / ファイルを読む / mvnを叩く
        これまでの全経緯 += 結果;           // ← 末尾に足す
    } else {
        break;                            // 文章を返してきた＝完了
    }
}
```

**役割分担はこうなっている**

|  | 誰が | 何を |
|---|---|---|
| 🧠 判断 | **LLM（1つだけ）** | 次に何をすべきか。毎回まっさらな1発の推論で決める |
| ⚙ 実行・接続 | **ただのプログラム** | ツールを実行し、結果を末尾に足して、もう一度LLMを呼ぶ |

> ❌ 指揮者AIがいて、専門AIに仕事を振っている ── ではない
> ✅ **同じ1つのモデルが、1行ずつ増えていく経緯を毎回読み直して、そのつど次の一手を決めている**

**ループが止まる3つの条件**
1. 🟢 目的達成（ビルドが通った、テストが緑になった）
2. 🟡 手詰まり（自分で直せないと判断した）
3. 🔴 上限到達（回数・トークンの上限に当たった）

### Take away
- ⏳ **待ち時間 ＝ AIの作業時間**。長いのは、それだけ仕事をしている証拠
- 🔍 **ログは最良のデバッグ情報**。「何を読んだか」「どこで詰まったか」が全部書いてある。うまくいかない時はまずログを遡る
- 🔧 **道具を与えるほど自走する**。ビルドやテストを実行させると、AIは自分で誤りに気づいて直せる（＝今日のCD／UTの構成そのもの）
- ⚠ **毎回「全経緯」を読み直している** ＝ ループが長引くほど経緯が膨らむ。これが次の話（→ 小話02 コンテキストオーバーフロー）に直結する

### 話すこと
- ChatGPTでチャットした時との一番の違いはここです。あちらは「文章を返して終わり」、今日のものは「目的を達成するまで自分で回り続ける」
- そして意外なのが**中身の素朴さ**です。裏で何体ものAIが連携しているように見えますが、実際には**賢い部分は1つのモデルだけ**で、周りはただのループなんです
- しかも各判断は毎回1発です。前回何を考えたかを覚えているわけではなく、**増えていく経緯を毎回まるごと読み直して**、そのつど決め直している
- だから止まった時に見るべきは、出力の最後ではなく**ループの途中**です。「設計書を読めていない」「同じエラーで3回ループしている」は、ログを見ればすぐ分かります
- ……そして、毎回まるごと読み直すということは、長く回すほど読む量が増えるということでもあります。それが次の小話につながります
