# 小話01　なぜAIはステートレスなのに会話が続くのか

|項目|内容|
|---|---|
|分類|🔧 仕組み|
|尺|5分（スライド2枚）|
|推奨タイミング|CD実行待ち（最初の待ち時間）|

## スライド1

### メインメッセージ
> **AIは「覚えて」いない。毎回、会話の全部を読み直している**

### 見せるもの

**掴み：「さっきの続きで」が通じる ＝ 覚えている、のか？**

**① 画面で見えている会話（3ターン）**
```
 あなた ： 消費税を計算する関数を作って
 AI     ： function calcTax(p){ return p*1.1 }
 あなた ： 軽減税率にも対応して
 AI     ： function calcTax(p, rate){ ... }
 あなた ： テストも書いて
```

**② そのとき実際にAIへ送信されている中身**
```
── 1ターン目の送信内容 ────────────────────────────
   user : 消費税を計算する関数を作って            ← 今回の入力

   ＝ AIが持っている情報は、この1行だけ

── 2ターン目の送信内容 ────────────────────────────
   user : 消費税を計算する関数を作って            ← 再送
   ai   : function calcTax(p){ return p*1.1 }     ← 再送
   user : 軽減税率にも対応して                    ← 今回の入力

   ＝ この3行を「初めて読む文章」として、まとめて渡している

── 3ターン目の送信内容 ────────────────────────────
   user : 消費税を計算する関数を作って            ← 再送
   ai   : function calcTax(p){ return p*1.1 }     ← 再送
   user : 軽減税率にも対応して                    ← 再送
   ai   : function calcTax(p, rate){ ... }        ← 再送
   user : テストも書いて                          ← 今回の入力

   ＝ 毎ターン、過去の全文がまるごと付いてくる
```

> もし「軽減税率にも対応して」の**一文だけ**を送ったら、AIは「何に対応するの？」としか答えられません。
> そうならないのは、AIが覚えているからではなく、**上の全文が毎回くっついて届いているから**です。

- AIの本体（モデル）は**前のやり取りを1文字も保持していない**
- 「記憶しているように見える」のは、**アプリ側が過去ログを溜めて、毎回くっつけて送っている**から
- つまり "セッション" の正体は、**会話ログを積んでいる入れ物**でしかない

**この構造から、そのまま導けること**

| 見た目 | 実際に起きていること |
|---|---|
| 会話が続く | 過去ログを毎回まるごと再送している |
| 話が長くなるほど遅い・重い | 読み直す量が毎ターン増えている |
| 新しいチャットだと通じない | 入れ物が空 ＝ 本当に何も知らない |

### 話すこと
- AI＝人間のように記憶している、というイメージを一度捨ててください。モデルは**呼ばれるたびに完全な初対面**です
- では、なぜ「軽減税率にも対応して」の一言で通じるのか。単純に、**過去の会話を全部くっつけて毎回送り直しているから**です。3ターン目には、1ターン目の質問も回答も、そっくりそのまま再送されています
- 今日使っているツールも同じです。ログを読んだ内容も、ビルドのエラーも、全部この"入れ物"に積み上がっています（→ 小話03のループで足しているのがココ）

## スライド2

### メインメッセージ
> **「入れ物の中身」を管理できる人が、AIをうまく使える**

### 見せるもの

**入れ物に入っているもの（今日の研修の場合）**
```
 ┌──────────── セッション（毎回まるごと送られる） ────────────┐
 │ ① システムプロンプト   AIの役割・使える道具の説明          │
 │ ② ルールファイル       CD_ルール.md など                   │
 │ ③ 読み込んだ設計書     Docsシステム/外部設計/…             │
 │ ④ これまでの全やり取り  指示・生成コード・エラー・修正      │
 └────────────────────────────────────────────────────────────┘
                ↑ ④だけが、放っておくとひたすら太る
```

**だから、こう扱う**

| 場面 | やること | 理由 |
|---|---|---|
| 話題が変わった | 🆕 **新しいセッションを開く** | 前の話題は邪魔なノイズにしかならない |
| おかしくなった | 🆕 **作り直す**（直し続けない） | 誤った出力もログに残り、後を汚染する（→ 小話11） |
| 覚えていてほしい事 | 📄 **ファイルに書く** | 会話に溜めるのではなく、設計書・ルールに置く |
| 長くなってきた | ✂ 区切る | 読み直す量が増え続け、やがて上限に当たる（→ 小話02） |

> 💡 **記憶は会話に溜めない。ファイルに置く。**
> これが今日の spec駆動開発のやり方そのもの（→ 小話10）

### Take away
- ✅ **AIに記憶はない**。あるのは「毎回まとめて渡している会話ログ」だけ
- ✅ 会話が長引くほど、**毎ターンの読み直し量が増える**（＝遅く・高く・不正確になる）
- ✅ **新しいセッションを開くことは、リセットではなく整理**。ためらわずに切る
- 📄 残したい情報は会話ではなく**ファイル**へ。それが次のセッションでも効く唯一の方法

### 話すこと
- ここが分かると、AIの挙動がかなり読めるようになります。「なぜ長い会話だと急に精度が落ちるのか」も、「なぜ新しいチャットだと話が通じないのか」も、全部この1つの構造で説明できます
- よくある失敗が、**1つのセッションを一日中使い続ける**ことです。関係ない過去のやり取りを毎回読ませ続けることになります
- 逆に、うまい人は**こまめに切ります**。そして残したいことは設計書やルールファイルに書く。今日やっていることは、まさにその形です
