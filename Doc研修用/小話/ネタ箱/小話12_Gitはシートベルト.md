# 小話12　Gitはシートベルト ― AI時代のコミット粒度

|項目|内容|
|---|---|
|分類|🛠 実務|
|尺|4分（スライド2枚）|
|推奨タイミング|機能追加フェーズの直前|

---

## スライド1

### メインメッセージ
> **AIは、あなたが思っているより広い範囲を書き換える**

### 見せるもの

**掴み：「関連する箇所も直しておきました」**
```
 依頼： 「BookDeleteController に削除確認を追加して」

 結果： Controller       修正  ← 頼んだもの
        Service          修正  ← 頼んでいない
        Mapper           修正  ← 頼んでいない
        テンプレート3枚   修正  ← 頼んでいない
        既存のテスト2本   修正  ← 頼んでいない ★危険
        ────────────────────
        計 8ファイル変更

 …この状態から「さっきの状態に戻して」と言えますか？
```

**AIの特性として、こうなる**

| 特性 | 結果 |
|---|---|
| 一貫性を保とうとする | 呼び出し元・関連クラスまで直しにいく |
| 止まらずに進む | 気づいた時には広範囲が変わっている |
| 悪気なく"良かれと思って"やる | 既存の動いていたコードまで書き換わる |
| 途中で止まることもある | **中途半端に変更された状態**が残る |

> ⚠ 一番怖いのは「壊した」ではなく「**どこが変わったか分からなくなる**」こと

### 話すこと
- 手で書いていた頃は、変更範囲は自分の頭の中にありました。AIに任せると、**変更範囲が自分の頭の外**に出ます
- しかもAIは親切なので、頼んでいない所まで整合性を取ろうとして直します。多くは正しいのですが、**既存のテストを直されるのは相当危険**です
- ここで唯一の安全装置がGitです。Gitは今までも大事でしたが、AI時代は**位置づけが変わります**

## スライド2

### メインメッセージ
> **「いつでも捨てられる状態」を保つのが、速さの前提条件**

### 見せるもの

**🔒 2つのタイミングだけ守る**
```
 ┌────────────────────────────────────────────┐
 │  ① AIに投げる前   →  コミット（きれいな出発点） │
 │  ② 動いたら即     →  コミット（戻れる着地点）   │
 └────────────────────────────────────────────┘

      投げる前 ●───── AIが暴れる区間 ─────● 動いた
               ▲                          ▲
          ここに戻れる                ここまで確保
```

**AI時代のコミット粒度**

| 従来 | AI活用時 |
|---|---|
| 機能が完成したら | **1回の指示ごと**でよい |
| きれいな単位で | 汚くてよい。**後でまとめられる** |
| メッセージを丁寧に | 「WIP: BK01削除 AI生成」で十分 |
| 変更を積み上げる | **捨てる前提**で積む |

**差分レビューが、そのまま作業になる**
```
 git diff / VSCodeのソース管理ビュー
        ↓
 ① 頼んでいないファイルが変わっていないか   ◄── 最初に見る
 ② 既存のテストが書き換えられていないか     ◄── 特に重要
 ③ 中身が仕様どおりか                     （→ 小話15）
```

### Take away
- ✅ **AIに投げる前にコミット**。これだけで、やり直しのコストがほぼゼロになる（→ 小話11）
- ✅ 粒度は細かくてよい。**きれいさより、戻れることが優先**
- ✅ レビューの入口は「**変更ファイル一覧**」。頼んでいない所が変わっていたら要注意
- 🚗 Gitはシートベルト。**事故らない自信ではなく、事故った時に助かるために締める**

### 話すこと
- 言っていること自体は当たり前です。ただ、AI活用では**この当たり前の効き目が桁違いに大きい**
- 戻れる状態があると、**思い切って任せられる**ようになります。逆に戻れないと、慎重になりすぎてAIの速さを活かせません
- 今日のハンズオンでも、CD実行の前・UT実行の前に一度コミットしてから進めてみてください。**安心して捨てられる**というのが、どれだけ作業を速くするか体感できると思います
