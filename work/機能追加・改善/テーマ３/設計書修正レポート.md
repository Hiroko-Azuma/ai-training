# 設計書修正レポート

## テーマ

書籍の検索機能に「出版社による検索」を追加する機能改善

## 要件

- 書籍の検索機能に「出版社による検索」を追加する
- 出版社はプルダウンで選択可能にする
- ただし出版社はDBでマスター管理するものではなく、既に登録されている書籍データより重複を排除してプルダウンに表示すること

## 対応方針

`prompt/00.設計/設計_Executor.md` の手順に従い、影響調査結果に基づいて **設計書のみ** を修正した。
アプリケーションのソースコード（`training-bookshelf/src` 配下）は本対応では一切変更していない。

画面レイアウトが変わる設計書（BK01）については、ルールに従い
`Docsシステム/外部設計/05個別画面設計/html/` のHTMLモックも修正し、`tools/screenCapture` で
スクリーンショット（`img/BK01.png`）を再生成した。

`books` テーブルには元々 `publisher`（出版社）列が存在しており、DBスキーマ自体の変更（列追加）は不要だった。
そのため本対応でのDB関連の修正は、検索・重複排除（`DISTINCT`）処理を高速化するための **インデックス追加** のみである。
出版社の値を管理するマスタテーブルは新設していない（要件どおり）。

## 1. BK01_書籍一覧画面.md（画面設計）

### 目的
検索条件エリアに「出版社」によるプルダウン検索を追加するため。出版社はDBでマスタ管理しないため、
`categories`（カテゴリマスタ）と異なり、`books` テーブルに実際に登録されている値を重複排除して選択肢化する処理を明記した。

### 修正内容

1. 「2.1 検索条件エリア」の項目定義表に `出版社`（`searchPublisher`、select、プルダウン選択・完全一致検索）の行を追加
2. 「出版社選択肢」の説明を追加し、`categories` のような固定マスタを持たず `books.publisher` 列からの `DISTINCT` 取得である旨を明記
3. 「3.1 初期表示処理」の処理内容・SQL・OUTPUTに、出版社選択肢の取得処理（`SELECT DISTINCT publisher ... ORDER BY publisher`）を追加
4. 「3.2 検索ボタン押下時」のINPUT・処理内容・SQL・OUTPUTに、出版社検索条件（完全一致）とセッション保存項目を追加
5. 「3.4 ソートリンク押下時」のOUTPUTに出版社選択肢の項目を追加（ソート後も画面を再描画するため）
6. 「6. メッセージ」に「出版社選択肢」の節を新設し、`bk01.publisher.all`（全て表示用）を追加
7. HTMLモック（BK01.html）の検索フォームに出版社プルダウンを追加し、既存3項目のカラム幅を `col-md-4` → `col-md-3` に変更（4項目を1行に収めるため）
8. 改訂履歴に版数 1.2 を追加

### Before（検索条件エリア 項目定義表）
```
| タイトル | searchTitle | text | - | 100 | - | 部分一致検索 |
| 著者名 | searchAuthor | text | - | 50 | - | 部分一致検索 |
| カテゴリ | searchCategory | select | - | - | 全て | プルダウン選択 |
| 検索ボタン | btnSearch | button | - | - | - | - |
| クリアボタン | btnClear | button | - | - | - | 検索条件をクリア |
```

### After
```
| タイトル | searchTitle | text | - | 100 | - | 部分一致検索 |
| 著者名 | searchAuthor | text | - | 50 | - | 部分一致検索 |
| カテゴリ | searchCategory | select | - | - | 全て | プルダウン選択 |
| 出版社 | searchPublisher | select | - | - | 全て | プルダウン選択（完全一致検索） |
| 検索ボタン | btnSearch | button | - | - | - | - |
| クリアボタン | btnClear | button | - | - | - | 検索条件をクリア |

**出版社選択肢:**
- 全て（値: ""）
- 既に登録されている書籍データ（booksテーブル）の出版社（publisher）を重複排除して表示

**選択肢の取得元:** booksテーブルのpublisher列から重複を排除（DISTINCT）して取得（昇順）。
出版社はcategoriesテーブルのようなマスタテーブルを持たず、DBでマスター管理しない。
```

### Before（3.1 初期表示処理 SQL 抜粋）
```sql
-- カテゴリ選択肢取得
SELECT category_id, category_name
FROM カテゴリテーブル
ORDER BY category_id

SELECT ... （書籍一覧取得）
```

### After
```sql
-- カテゴリ選択肢取得
SELECT category_id, category_name
FROM カテゴリテーブル
ORDER BY category_id

-- 出版社選択肢取得（重複排除）
SELECT DISTINCT 出版社
FROM 書籍テーブル
ORDER BY 出版社

SELECT ... （書籍一覧取得）
```

OUTPUTにも `出版社選択肢 | DTO | 重複排除済みの出版社名リスト` を追加した。

### Before（3.2 検索ボタン押下時 SQL 抜粋）
```sql
WHERE 書籍テーブル.タイトル LIKE :タイトル        -- 入力がある場合のみ
  AND 書籍テーブル.著者 LIKE :著者名              -- 入力がある場合のみ
  AND 書籍テーブル.カテゴリ = :カテゴリ            -- 「全て」以外が選択された場合のみ
```

### After
```sql
WHERE 書籍テーブル.タイトル LIKE :タイトル        -- 入力がある場合のみ
  AND 書籍テーブル.著者 LIKE :著者名              -- 入力がある場合のみ
  AND 書籍テーブル.カテゴリ = :カテゴリ            -- 「全て」以外が選択された場合のみ
  AND 書籍テーブル.出版社 = :出版社                -- 「全て」以外が選択された場合のみ
```

INPUTに `出版社 | リクエスト | 任意。「全て」選択時は条件なし。完全一致` を、
OUTPUTに `出版社選択肢 | DTO | 重複排除済みの出版社名リスト` と `検索条件（出版社） | セッション | -` を追加した。

### 画面イメージ（HTMLモック / PNG）

検索条件エリアに出版社プルダウンを追加し、4項目（タイトル・著者名・カテゴリ・出版社）が1行に収まるよう
`col-md-4` × 3列 → `col-md-3` × 4列 のレイアウトに変更した。

- Before: タイトル / 著者名 / カテゴリ（3項目、`col-md-4`）
- After: タイトル / 著者名 / カテゴリ / 出版社（4項目、`col-md-3`）

修正後のスクリーンショットは [img/BK01.png](../../Docsシステム/外部設計/05個別画面設計/img/BK01.png) を参照。

## 2. 06メッセージ一覧.md（メッセージ設計）

### 目的
出版社プルダウンの「全て」表示用メッセージIDを定義するため。
出版社名そのもの（個々のプルダウン選択肢）は `books` テーブルの実データから動的に取得するため、
カテゴリ（`category.fiction` 等）のように選択肢ごとのメッセージリソース化は行わない。

### 修正内容
「3.1 書籍一覧画面（BK01）」の `properties` ブロックに `bk01.publisher.all` を追加した。

### Before
```properties
# 書籍一覧画面
bk01.message.nodata=書籍が登録されていません
bk01.message.searchresult={0}件の書籍が見つかりました
```

### After
```properties
# 書籍一覧画面
bk01.message.nodata=書籍が登録されていません
bk01.message.searchresult={0}件の書籍が見つかりました
bk01.publisher.all=全て
```

改訂履歴に版数 1.1 を追加した。

## 3. 04TBL定義.md（DB設計）

### 目的
出版社検索の追加に伴い、`books.publisher` 列を用いた検索（完全一致）およびプルダウン選択肢の
重複排除取得（`DISTINCT`）を高速化するため、インデックスを追加するため。
出版社をマスタ管理する要件はないため、テーブル追加や列追加（DBスキーマ変更）は行っていない。

### 修正内容
1. booksテーブル定義表の `publisher` 行の「インデックス」欄を `-` → `○` に変更し、備考に追加理由を記載
2. インデックス定義表に `idx_publisher` 行を追加
3. 「1. booksテーブル」節の `CREATE TABLE books` 文に `INDEX idx_publisher (publisher)` を追加
4. 「6. 全テーブル作成スクリプト」節の `CREATE TABLE books` 文（重複定義箇所）にも同様に追加
5. 改訂履歴に版数 1.4 を追加

### Before（テーブル定義表 抜粋）
```
| 4 | publisher | 出版社 | VARCHAR | 50 | - | NOT NULL | - | - | - | - | - | - |
```

### After
```
| 4 | publisher | 出版社 | VARCHAR | 50 | - | NOT NULL | - | - | - | - | ○ | 出版社検索用にインデックスを追加 |
```

### Before（インデックス定義表 抜粋）
```
| idx_isbn | UNIQUE | isbn | ISBN重複チェック、ISBN検索 |
| idx_title | INDEX | title | タイトル検索の高速化 |
| idx_author | INDEX | author | 著者検索の高速化 |
| idx_category_id | INDEX | category_id | カテゴリフィルタの高速化 |
| idx_published_date | INDEX | published_date | 出版日ソートの高速化 |
```

### After
```
| idx_isbn | UNIQUE | isbn | ISBN重複チェック、ISBN検索 |
| idx_title | INDEX | title | タイトル検索の高速化 |
| idx_author | INDEX | author | 著者検索の高速化 |
| idx_publisher | INDEX | publisher | 出版社検索の高速化、選択肢（DISTINCT）取得の高速化 |
| idx_category_id | INDEX | category_id | カテゴリフィルタの高速化 |
| idx_published_date | INDEX | published_date | 出版日ソートの高速化 |
```

### Before（CREATE TABLE文 抜粋）
```sql
CREATE TABLE books (
    ...
    UNIQUE KEY idx_isbn (isbn),
    INDEX idx_title (title),
    INDEX idx_author (author),
    INDEX idx_category_id (category_id),
    INDEX idx_published_date (published_date),
    ...
);
```

### After
```sql
CREATE TABLE books (
    ...
    UNIQUE KEY idx_isbn (isbn),
    INDEX idx_title (title),
    INDEX idx_author (author),
    INDEX idx_publisher (publisher),
    INDEX idx_category_id (category_id),
    INDEX idx_published_date (published_date),
    ...
);
```

同一のCREATE TABLE文が「6. 全テーブル作成スクリプト」にも重複定義されているため、そちらも同様に修正した。
